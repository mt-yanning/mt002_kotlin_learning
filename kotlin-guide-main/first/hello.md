# "Hello World!"

The canonical starting point with any new language is a program that prints
"Hello World!" on the screen. In this section, we take you through the
steps needed to create such a program, compile it, and run it.

**Note: this work must be done within the `tasks/task1_1` directory of your
repository.** If you don't have this repository yet, see the [earlier
instructions][prep] on how to fork and clone it.

## Project Configuration

Start by creating a file named `module.yaml` in the `tasks/task1_1` directory:

This file should contain a single line:

```yaml
product: jvm/app
```

This configures the Kotlin Toolchain, telling it that you wish to create an
application that runs on the [Java Virtual Machine][jvm] (JVM). It is possible
to target other platforms, but we will be running on the JVM for all of these
tasks.

By default, the toolchain assumes that you want to use version 2.3.20 of
Kotlin and version 21 of the Java Development Kit (JDK). It will download
these versions if it can't find them on your system. We will discuss later
how you can [change these settings][set] (e.g., to make the toolchain use a
specific JDK that is already installed on your system).

## Source Code

The next step is to create a file named `Main.kt`, containing the three lines
of code shown below. Save this file to the `src` subdirectory of
`tasks/task1_1`.

:::{tip}
:class: dropdown
You can use the 'Copy to Clipboard' button that appears in the top-right
of the code panel to help with this, but **we strongly recommend that you
actually type in the code**, as this will help you acclimatize more rapidly
to Kotlin features and syntax.
:::

```kotlin
fun main() {
    println("Hello World!")
}
```

This simple program illustrates several aspects of Kotlin:

- Functions are defined using `fun`, and the start of the function body
  is marked by a left brace, `{`, as in C.

- Kotlin recognizes a function named `main` as the entry point for a program,
  just like C does.

- Printing to the console is similar to Python, except that Kotlin has
  *two* functions for this, named `println` and `print`. The former prints
  a newline at the end of the given string, whereas the latter does not.

- **There is no semi-colon at the end of the statement!** Kotlin hardly ever
  requires them[^semi].

- A right brace, `}`, marks the end of the function body. Like C, Kotlin uses
  pairs of braces to define blocks, rather than following Python's approach of
  using indentation.

## Compiling & Running

In a terminal window, cd to the `tasks/task1_1` directory of your repository.
Then try to compile the program by entering

    kotlin build

**This will be very slow the first time that you try it**, because it will
need to download toolchain components. It may also download a Java Development
Kit (JDK), if it can't find the version it is expecting to use already
installed on your PC.

Subsequent attempts to compile or run the program will be much faster.

:::{warning} Troubleshooting
If the command fails, check that you are in the directory containing the
`module.yaml` file, and that the `Main.kt` file is in a subdirectory
named `src`.

Check also that the Kotlin Toolchain is accessible. If you are doing this
on a SoCS Linux machine, have you set it up using the `module add kotlin`
command? If you are trying this on your own PC, have you installed the
Kotlin Toolchain yet?
:::

Now try running the program with

    kotlin run

You should see "Hello World!" appear on the screen.

Edit `Main.kt`, change the message displayed by the program, and save your
changes. Then repeat the `kotlin run` command. You'll see from this that it
isn't necessary to rerun the `build` command explicitly; the toolchain will
do this for you if it detects that the compiled code is out of date with
respect to the source code.

## Compiler Output

If you list directory contents, you should see that a new directory named
`build` has appeared. This contains everything generated by the compiler.

Inside `build`, there should be a subdirectory named `tasks`, and inside
there another subdirectory named `_task1_1_jarJvm`. Inside here you should
see a single [**JAR file**][jar]. This contains all of the Java bytecode
generated by the compiler. When you use the `kotlin run` command, this code
will be loaded and executed by the JVM.

You see this particular output from the compiler because the JVM is the
target. If the build had been configured to use a different target, you would
see something different here (e.g., a native executable, like those you
generated from C code last year).

:::{note}
If you check the `.gitignore` file at the top level of your repository,
you'll see that it includes a line instructing Git to ignore the
`build` directory.

**You should do the same when you create your own repositories for Kotlin
code.** Compiler output should never be put under version control, because
it can always be regenerated easily from source code.
:::

## Other Things to Try

You can reduce the amount of logging using the `--log-level` option:

    kotlin --log-level=off run

You can also remove all compiler output with

    kotlin clean

Try both of these commands to see exactly what they do.

:::{tip}
Get into the habit of using the `clean` command when you have finished
working with a program.

This will ensure that you are not wasting disk space unnecessarily.
(This matters on SoCS Linux machines, where you have a limited quota
of disk space.)
:::
